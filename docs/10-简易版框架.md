## 一、一句话

每个地区一个组，里面直接是这个地区的全部节点，点哪个用哪个；选中的节点挂了不会自动换，要换就回组里点别的。“国外默认”是七个地区，后面接全部节点。和完整版并存，文件名带 `-simple`。

## 二、使用者定的

1. 另出一版简易版，和完整版并存；Loon、Quantumult X、Stash 的简易版也分普通、严格两份（2026-10-20）。
2. **纯手选**：“直接一个地区所有节点都有 我自己选 不自动换 最省事”（2026-10-21）。没有“X·自动”这类组。
3. “国外默认”放七个地区和全部节点，自由选；首次默认日本（和完整版一样）。
4. **完整版不改**（“完整版都写完了”）。
5. “国外默认”选了单个节点时的 DNS：方案 2（“1②”）——mihomo、sing-box 的简易版里，境外 DNS 和规则数据的下载另走一个内部的自动测速组，不跟着手选的节点（第六节）。
6. 检查间隔 1 小时。纯手选以后，用到它的只剩内部组“境外DNS”和 mihomo 订阅上的检查。
7. 新加的组，图标用图标仓库里现有的图（“图标就用旧的”）：“境外DNS”借用“国外默认”的图。
8. 写好以后送 GPT 审（“写 写完我让 GPT 审核”）。

## 三、结构

```
服务组（OpenAI、YouTube 等，和完整版一样）
  └ 选一个：国外默认 / 香港 / 日本 / 韩国 / 台湾 / 新加坡 / 美国 / 其他地区 / 直连（各组的默认和完整版相同）

日本（六个明确地区都一样）
  ├ 日本 01
  ├ 日本 02 …… 这个地区的全部节点（含名字说不清落地的）。点一个 = 固定用它，挂了不会自动换

其他地区：其他节点，手选
国外默认：日本 / 香港 / 韩国 / 台湾 / 新加坡 / 美国 / 其他地区，后面接全部节点（首次默认日本）
PayPal·美国固定、广告拦截、国内直连：和完整版一样
境外DNS（只在 mihomo、sing-box）：内部用，只管境外 DNS 和规则数据的下载，不管网页和 App 的连接走哪里
```

### 3.1 各组

| 组 | 类型 | 成员 | 首次导入时选中 | 和完整版比 |
|---|---|---|---|---|
| 服务组（43 个；sing-box 是 42 个，它的“广告拦截”是规则动作，不是组） | 选择 | 照旧 | 照旧 | 成员、默认不变；“国外默认”“PayPal”两个组的说明按简易版改写（`source/groups.yaml` 的 `note_simple`） |
| 六个地区 | 选择 | 这个地区的全部节点（宽筛选，和完整版的“X·手动”是同一条） | 第一个节点（各端的“第一个”见第四节） | 完整版里这是“选模式”的入口 |
| 其他地区 | 选择 | 其他节点 | 第一个 | 不变 |
| 国外默认 | 选择 | 七个地区，后面接全部节点 | 日本 | 多了全部节点 |
| PayPal·美国固定 | 选择 | 美国节点（宽筛选） | 第一个 | 不变 |
| 境外DNS（只在 mihomo、sing-box） | 自动测速 | 六个明确地区的严筛选取并集（不含“其他地区”） | — | 新加的。mihomo 上藏起来 |
| 去掉的 | — | 每个地区的手动优先、手动、自动、故障转移、负载均衡，共 30 个 | — | — |

- **宽筛选、严筛选**：现有的按名字分地区的两套正则（`docs/02`“节点名称分地区”）。宽的收这个地区的全部节点，包括名字说不清落地的（人来选的组用）；严的只收名字只指向这个地区的（让内核自己挑节点的组用）。
- **全部节点**：订阅里的全部节点，去掉机场插进来的提示行（“剩余流量”“套餐到期”等）和本项目的占位（Stash、sing-box 上的“…·无可用节点”）。第五节。
- **“境外DNS”为什么只用六个地区的严筛选**：“其他地区”里可能有回国节点，延迟最低、会被自动测速挑中，但出口在国内，境外 DNS 走它就失去了意义；说不清落地的节点（例如名字里有两个地区）也不放进来。
- **地区一个节点都没有时的处理和完整版一样**：mihomo 写 `empty-fallback: REJECT`，sing-box 放一个拒绝连接的占位出站，Stash 放一个连不上的占位节点，都是连接失败而不是直连；Loon、Quantumult X 上筛选为空时会怎样，没有依据（`docs/02`“节点筛选为空时”）。“国外默认”里有写明的七个地区，不会是空的。

### 3.3 怎么用（写给使用者）

- 服务组里选地区，例如 OpenAI 选“日本”；“日本”里点一个节点，就固定用它。只有这一层。
- 节点挂了不会自动换：回到“日本”里点别的节点。
- “国外默认”里选地区或者直接点节点都可以，直接点的节点挂了一样不会自动换。
- **Stash**：第一次导入以后，先在用到的地区组里点一个真节点（第 4.4 节：首次选中的可能是连不上的占位节点）。
- **SFA**：会多看到一张“境外DNS”卡片，点不动；很多网站同时打不开、而你选的节点是好的时，对“境外DNS”点一下“测速”（第六节）。
- DNS 泄露：Loon、Quantumult X、Stash 想让走代理的网站名字不经过国内 DNS，用严格版（例如 `loon-simple-strict.conf`）；Clash、SFA 两种都不会把走代理的域名交给国内 DNS（`docs/03`，和完整版相同）。

## 四、各端怎么写、依据

### 4.1 Loon

- 写法：`日本 = select,F-JP`（`F-JP` 是现有的宽筛选）；`国外默认 = select,日本,香港,韩国,台湾,新加坡,美国,其他地区,F-ALL`；`F-ALL` 是新加的一条 `[Remote Filter]`（全部节点）。
- **事实（官方示例）**：`example.conf` 第 77 行 `PROXY = select,Auto,1,2,3,4,Subs`，一个选择组里混放了策略组（Auto）、节点（1–4）和整份订阅（Subs）；第 67 行 `[Remote Filter]` 的注释是“筛选订阅节点，筛选后的结果可加入到策略组中”。
- **事实（真机，2026-10-20）**：完整版的 `香港·手动 = select,F-HK` 这类写法，组里是对应地区的节点（`docs/05`“真机记录”第 2 项）。简易版的地区组就是这种写法。
- **推断**：“策略组名 + 筛选”混放在一个选择组里可以用——官方示例混放的是组和订阅，没有“组和筛选”一起的例子。要在真机上看“国外默认”的成员：前七项是七个地区，后面是节点。
- 首次选中：推断是组里第一项（日本组是第一个日本节点；国外默认是日本）。

### 4.2 Quantumult X

- 写法：`static=日本, server-tag-regex=<宽筛选>`；`static=国外默认, 日本, 香港, 韩国, 台湾, 新加坡, 美国, 其他地区, server-tag-regex=<全部节点>`。简易版只有 `static`，没有自动类的策略。
- **事实（官方 sample.conf，提交 `af6fb59`）**：第 105–113 行只有两种分开的例子：写明成员的（`static = policy-name-1, Sample-A, Sample-B, Sample-C`），和用正则筛的（`static = policy-name-5, resource-tag-regex=…, server-tag-regex=…`）；**没有写明成员和正则混在一起的例子**。完整版从来没有这样混写过。
- **未知**：“国外默认”的混写能不能用。地区组只用正则，和完整版的“X·手动”是同一种写法。
- 混写不行时的退路（没有做）：“国外默认”只写七个地区和一个中间组“全部节点”，中间组 `static=全部节点, server-tag-regex=<全部节点>`。代价：点具体节点要多点一层；多一个新组名，要一张图（借用现有的，或者你传一张）。
- 首次选中：推断是第一项。

### 4.3 mihomo（Clash Verge Rev、Clash Meta for Android）

- 写法：`日本` = select，`include-all-providers: true`，`filter: <宽筛选>`，`empty-fallback: REJECT`；`国外默认` = select，`proxies: [日本, 香港, 韩国, 台湾, 新加坡, 美国, 其他地区]`，再加 `include-all-providers` + `filter: <全部节点>`；`境外DNS` = url-test，`filter` 是六条严筛选用反引号连起来，`interval: 3600`，`max-failed-times: 3`，`hidden: true`，图标借“国外默认”的。
- **事实（源码 v1.19.31）**：写明的成员组成一个排在最前面的集合，而且不过筛选（`adapter/outboundgroup/parser.go:183`，`groupbase.go:147`“compatible provider unneeded filter”）；`filter` 按反引号拆成几条正则，取并集、去重，按筛选的先后排（`groupbase.go` 的 `NewGroupBase`、`GetProxies`）；选择组默认选第一个，记住的选择不在成员里时也回到第一个（`selector.go:103-111`）。
- **事实（官方内核实测，`tools/check_official.py`）**：用 2,290 个假节点实际分组：六个地区和“其他地区”的成员和 Python 按同一条正则算的逐个相同（香港 117、日本 109、韩国 30、台湾 42、新加坡 29、美国 187、其他地区 1,755）；“国外默认”2,259 项，前七项是写明的七个地区、后面 2,252 个节点，首次选中日本；地区组首次选中第一个节点；“境外DNS”425 个节点，正好是六个地区严筛选的并集，类型是自动测速、`hidden` 为真（`docs/evidence` 不变，这次的输出见第八节）。
- **境外 DNS**：`nameserver` 和 `nameserver-policy` 里的境外 DoH 写成 `https://1.1.1.1/dns-query#境外DNS`（`config/config.go` 的 `parseNameServer`：`#` 后面是组名）。**事实（源码）**：组名不存在时内核不报错，而是把它当成网卡名（`tunnel/dns_dialer.go:72-76`），DNS 就悄悄断了——写盘前检查（`generator/verify.py`）对每个这样的地址核对组名真的存在。
- **GEO 数据的下载**：内核按规则下载（地址在 `testingcf.jsdelivr.net`）。简易版在“要真实地址的名单”之后加一段 `DOMAIN,testingcf.jsdelivr.net,境外DNS`，不跟着“国外默认”里手选的节点。
- 订阅上的检查间隔 3600 秒（mihomo 按订阅上的间隔检查，组上的间隔在地址相同时不起作用，`adapter/provider/healthcheck.go:70`）。
- **未验证**：Clash Verge Rev、Clash Meta for Android 的界面里，藏起来的“境外DNS”是不是真的看不到。

### 4.4 Stash

- 写法：`日本` = select，`include-all: true`，`filter: <宽筛选>`；`国外默认` = select，`proxies: [七个地区]`，再加 `include-all: true`、`filter: <全部节点>`。和完整版一样，每条筛选开头多一段，整个名字是内置策略（DIRECT、REJECT、REJECT-DROP）的不选；“国外默认”那条另外不选七个占位节点（8,473 字节）。
- **事实（2026-10-13 下载的官方文档“策略组”页）**：“策略组可以包含另一个策略组”；`select` 的例子里 `proxies` 混放了节点和组；“可以通过 `include-all: true` 引用所有的代理和远程代理集”；“支持 `filter` 字段，通过正则表达式过滤节点”。
- **未知**：`proxies` 和 `include-all` + `filter` 写在同一个组里时谁排在前面、`filter` 管不管写明的成员——文档没写。就算管：七个地区的名字都能通过“国外默认”那条筛选（`tests/test_simple.py` 核对）。`include-all` 包不包括策略组，文档也没写（完整版的“其他地区”有同样的未知，`docs/06`）。
- **风险（推断）**：地区组里有本地区的占位节点（“日本·无可用节点”，连不上）。如果 Stash 把配置里 `proxies` 段的占位节点排在订阅节点前面、首次导入时选第一个，那么各地区组首次选中的都是占位节点，走这些地区的连接失败（不会直连），要先手点一个真节点。完整版没有这个问题（默认走“手动优先”，占位节点只在“X·手动”里）。**没有改的原因**：去掉占位节点，地区一个节点都没有时组是空的，Stash 当作直连。
- `hidden` 不用（文档快照里没有），简易版的 Stash 也没有要藏的组。

### 4.5 sing-box（SFA）

- 写法：地区组 = selector，成员是生成时按宽筛选挑出的节点（一个都没有时是“无可用节点”占位，拒绝连接）；`国外默认` = selector，七个地区再接全部节点，`default: 日本`（没有节点时只有七个地区，不放占位）；`境外DNS` = urltest，`interval: 3600s`、`idle_timeout: 3600s`；`dns-foreign` 的 `detour`、规则集下载（1.14 的 `http_clients`，1.12 的 `download_detour`）都是“境外DNS”。
- **事实（源码 1.14.1）**：sing-box 要求检查间隔不超过 `idle_timeout`（`protocol/group/urltest.go:232-234`），超过时 `sing-box check` 照样通过、内核启动才失败——完整版写的是 30 分钟，简易版间隔 1 小时，所以 `idle_timeout` 取和间隔相同；写盘前检查核对这一点（完整版、简易版都查）。
- **事实（官方程序）**：`sing-box check` 在 1.14.1、1.12.0 上通过（模板和带样例节点的两种）；实测见第六节。
- 节点是生成时写进配置的，完整版和简易版共用同一批转换好的节点：节点改名时避开两版全部的组名（`emit_singbox.reserved_tags`）。

### 4.6 能不能在“日本”一个组里做到“我选一个节点，它挂了自动换同地区别的”

使用者 2026-10-21 问过（`docs/00`）。结论：除了 mihomo 的内核，都做不到；要做到就得两层组（完整版的“手动优先”）。Loon 在自动组里点节点选不中（真机，`docs/05`）；SFA 只能在 selector 里点选（`daemon/started_service.go:595`、`:757`）。使用者因此定了纯手选：不自动换，最省事。想要“我选的优先、挂了自动换、好了换回来”，用完整版的“X·手动优先”。

## 五、“全部节点”这条筛选

- 拼法：`generator/regions.py` 的 `compose_any`。不是提示行、也没有被本地指定成“不进任何组”的节点都收；等于宽的七条取并集（六个地区的宽筛选都要求名字里提到这个地区，“其他地区”收剩下的；名字里没有任何地区字样时，两边用的是同一个“提示行常用词”判断）。
- 大小：8,254 字节（带本地补充样例的 8,593 字节；项目自己定的上限是 16,000）。Stash 那一份 8,473 字节。
- 核对（事实，第八节的日志）：
  - 两万多个样本名（手写期望的样本、CLDR 国名、时区城市、词表组合）上，它、宽的七条取并集、逐步判断三者完全相同；随机拼的名字（公开词表 2 万个、带本地补充 6 千个）也相同；
  - ICU 74 上和 Python 完全相同（2,290、2,313 个节点名），长名字上和别的 13 条一起按时结束；
  - 官方 mihomo 用 2,290 个假节点实际分组，“国外默认”收进的节点和 Python 算的相同，提示行一个都没进来。
- mihomo“境外DNS”的筛选是六条严筛选用反引号连起来（78,504 字节）。它不和 16,000 字节的上限比：那个上限是给 Loon、Quantumult X 一行里的正则定的；mihomo 按反引号拆开以后每条都和完整版的“X·自动”相同。

## 六、境外DNS：境外 DNS 和规则下载不跟着手选的节点

### 6.1 为什么要它

“国外默认”能选单个节点以后，选中的节点挂了会连累 DNS：mihomo 上没被规则认出的网站全部 502、境外 DNS 会答国内地址的网站也 502、手动切成直连的组 502、UDP 被丢、系统联网检测得到 SERVFAIL；sing-box 上没被规则认出的域名解析失败、连接被关掉（2026-10-21 上午的实验，`handoff/notes/simple_mihomo/runs/e3v2.out`、`handoff/notes/simple_singbox/runs/dnsdep-*`）。使用者选了方案 2：另走一个内部的自动测速组。

### 6.2 写法

- mihomo：境外 DoH 写成 `https://1.1.1.1/dns-query#境外DNS`；GEO 数据下载主机交给“境外DNS”（第 4.3 节）。
- sing-box：`dns-foreign` 的 `detour`、规则集下载走“境外DNS”（第 4.5 节）。
- Loon、Quantumult X、Stash：DNS 用的是国内 DNS、直接发出，不经代理，没有这个组。
- 代价（推断，没有实测）：境外 DNS 的出口和你选的节点可能不在同一个地区。境外 DoH 按“境外DNS”节点所在的地方给 CDN 地址；走代理的连接多数把域名交给节点、由节点自己解析，不受影响，但 sing-box 上没被域名规则认出的网站、mihomo 上经节点转发的 UDP（例如 QUIC），用的是本机这样解析出来的地址，可能连到离你选的节点较远的 CDN 服务器（`docs/03` 最后一节）。

### 6.3 官方内核实测（2026-10-21，`handoff/notes/simple_mihomo/` 的 E6、E7）

用生成器实际写出的简易版配置（mihomo 是 `dist/` 里的那份，sing-box 是带实验台节点生成的那份），只把订阅 / 入站 / DNS 服务器换成本机的实验台和替身，境外 DNS 走的路不变。实验台的节点是 SOCKS5，只监听 127.0.0.1。

| 情况 | mihomo v1.19.31（E6） | sing-box 1.14.1、1.12.0（E7） |
|---|---|---|
| “国外默认”选的节点（美国 02）端口关闭 | 没被规则认出的境外网站 502（连接本身走的就是这个节点）；境外 DNS 会答国内地址的网站直连成功；系统联网检测几个名字解析正常；手动切成直连的组正常；UDP 照常发出；GEO 数据下载连到“境外DNS”当时用的节点（日本 01），没有经过挂掉的节点 | 没被规则认出的名字照样经“境外DNS”解析成功，国内地址的交给“国内直连”；境外的连接失败（走的是挂掉的节点） |
| 同上，节点不回话 | 同上 | 没测 |
| “境外DNS”自己用的节点端口关闭 | 2.12 秒以后恢复（换到香港 01） | 60 秒里每 5 秒一次、12 次解析全部失败；对“境外DNS”手动测一次速以后马上换到香港 01，之后都成功 |
| “境外DNS”自己用的节点不回话 | 14.19 秒以后恢复 | 没测 |

- mihomo 恢复以前的那几秒，要靠境外 DNS 判断的连接不是失败，而是解析不出地址、没能被 `GEOIP,CN` 认成国内，落到最后的“国外默认”（走了代理）。mihomo 的恢复不用等 1 小时一次的检查：连接被拒马上重测，其他失败按 `max-failed-times: 3` 计数（`adapter/outboundgroup/groupbase.go`）。
- sing-box 的自动测速组不因为连接失败而重测，只在定时检查时换节点（1.14.1 `protocol/group/urltest.go`）：简易版 1 小时一次，没在用时约 2 小时（源码推断，`docs/06` 已记的“没在用的节点约两个间隔才复测”）。
- 没有测的：实验台的“连上节点但出不去”“握手后回失败”两种模式只影响新连接，mihomo 的 DNS 连接是开着的旧连接，测不到东西，没有收进结论；真实机场的协议（不是 SOCKS5）、手机、真实网络都没有测。

### 6.4 1 小时检查的后果

- mihomo：“境外DNS”用的节点挂了，实测几秒到十几秒恢复（上表）。1 小时的间隔主要影响“节点在没有流量时挂了”这种，等有流量时才会发现。
- **sing-box（SFA）**：“境外DNS”用的节点挂了以后，最长约 1 小时（没在用时约 2 小时）里，没被规则认出的网站都打不开——包括不在国内域名集合里的国内网站；规则集也更新不了。对“境外DNS”点一下“测速”马上恢复。这是“1 小时检查”在简易版里唯一明显的代价，列在 `docs/06`“需要你决定的事项”，请你看过再定要不要改。
- Loon、Quantumult X、Stash：没有自动测速组，间隔用不到。
