## 节点名称分地区（2026-10-02）

词表在 `source/regions.yaml`，拼正则和逐步判断的代码在 `generator/regions.py`。四个客户端用同一套规则；名称只是初筛，不证明实际出口。

### 判断顺序

| 步骤 | 规则 | 例子 |
|---|---|---|
| 0 | `local.yaml` 里指定了地区的节点，按指定；信息节点（剩余流量、到期、官网、“过滤掉 N 条线路”等）不进任何组 | `剩余流量：10 GB` → 不进组；`香港 03 大流量` 是真节点 → 香港 |
| 1 | 名字里有“有效”的国旗：按国旗。六个地区以外的国旗都算其他国家 → 其他地区。🇨🇳、🇪🇺、🇺🇳 不当依据（不少机场用 🇨🇳 标台湾、香港节点） | `🇺🇸 香港 01` → 美国；`🇨🇳 台湾 07 家宽` → 台湾；`🇬🇧 日本 01` → 其他地区 |
| 2 | 没有有效的国旗：看文字。先去掉处在“中转 / 入口”位置的词，再看剩下的；有其他国家的词 → 其他地区 | `美国 01 \| 日本中转` → 美国；`日本 英国 01` → 其他地区 |
| 2′ | 词全在中转位置、名字里又只提到一个地区：仍归这个地区 | `日本中转 01` → 日本 |
| 3 | 香港让位：名字里同时有别的地区（或其他国家）时归对方，因为香港在节点名里多半是中转 | `深港专线 日本 01`、`香港-日本 01` → 日本 |
| 4 | 两个（或更多）不让位的地区都像落地、说不清：这几个组都进，检查工具单独列出 | `日本-美国 01` → 日本、美国 |
| 5 | 其余非信息节点 → 其他地区 | `Premium 01`、`DE-01`、`LA-01` → 其他地区 |

“有效”的意思：后面没有箭头（`→` `->` `=>` 等，箭头前面的是入口）；前面不是 `via`、`经`、`解锁`（`via` 要单独成词，`Latvia` 里的不算）；文字还要求后面不紧跟 `中转`、`中继`、`转`、`入口`、`解锁`、`relay`、`transit`（所以 `日本转美国 01` 归美国）。连在一起的国旗按两个字符一组读（`🇨🇳🇺🇸` 中间两个字符凑起来是另一面旗，不能认）。英文词和代码前后不能紧挨英文字母（`US` 不会命中 `RUS`、`AUS`、`Plus`），词里的空格可以是空格、下划线、连字符，也可以没有。

按这些规则，任何非信息节点至少进一个组（“其他地区”是其余六个组的补集），不会丢节点；“其他地区”不会和六个地区同时出现。

没有收的写法（会进“其他地区”，检查工具会列出来，可在 `local.yaml` 里补）：单个字的简称（`日`、`美`、`韩`、`台`、`新`；“港”除外）、`LA`、`SEA`、`SJ`、其他国家的两三位代码、紧挨着其他字母的代码（`HKIPLC01`）。已知会分错的写法记在 `tests/node_names.yaml` 的 `known_limits` 里，例如 `港转美 01`：认得“港”在中转位置，认不出单个字的“美”，结果归香港（检查工具会把它列在“按中转 / 让位规则判断”里）。

### 各端怎么执行、依据是什么

| 客户端 | 怎么用这条正则 | 依据 | 性质 |
|---|---|---|---|
| mihomo | 策略组 `filter`，按反引号拆成多条，每条 `regexp2.MustCompile(filter, regexp2.None)`；从订阅取节点后逐个 `MatchString(节点名)` | 源码 v1.19.31 `adapter/outboundgroup/groupbase.go`（`NewGroupBase`、`GetProxies`）；regexp2 v1.12.0（`go.mod`） | 事实（源码 + 官方内核实际运行） |
| sing-box | 不支持订阅；生成器把节点转换进配置时，用 Python 的 `re` 按同一条正则分好组 | `generator/emit_singbox.py` | 事实 |
| Loon | `[Remote Filter]` 一行：`名称 = NameRegex, FilterKey = "正则"` | 官方文档“节点筛选”页 https://nsloon.app/docs/Node/nodefilter ：NameRegex“使用正则表达式筛选节点名称”，常用正则里有 `^(?!.*A)`、`^(?!.*?B).*A`（否定前瞻）；行语法见官方示例配置。文档没有说用的是什么正则引擎 | 否定前瞻：事实（官方示例）；引擎：推断 |
| Quantumult X | 策略行的参数 `server-tag-regex=正则` | 官方 `sample.conf`：注释“Param resource-tag-regex and server-tag-regex only work for static, available and round-robin type of polices”，示例里 static、available、round-robin、dest-hash、url-latency-benchmark 五种都带了 `server-tag-regex` | 参数存在：事实；“自动”“负载均衡”两种策略是否按正则取节点：官方说法不一致，未验证；引擎：推断 |

推断：Loon 与 Quantumult X 都是苹果平台的原生应用，节点筛选用的是系统自带的 `NSRegularExpression`，它建立在 ICU 之上。这一条没有官方说明，只有旁证（官方和社区示例里用到的 `(?i)`、前瞻等写法 ICU 都支持）。

### 正则只用哪些写法

三个引擎（regexp2、ICU、Python）都支持的：`(?i)`、非捕获分组、交替、字符类、`.*`、`^` `$`、否定前瞻 `(?!…)`、定长的否定后顾 `(?<!…)`、`\s`、`\xHH`。

不用的：肯定前瞻 `(?=…)`（含等号；“名字里某处有 X”写成双重否定 `(?!(?!.*X))`）、`\b` `\d` `\w`（各引擎对 Unicode 的处理不同）、`{n,m}`、命名分组、占有量词、`\u` 转义。

不出现的字符：英文逗号（Loon、Quantumult X 用它分隔参数）、双引号（Loon 用它包住正则）、反引号（mihomo 用它分隔多条正则）、等号、空格、换行。词表或节点名里有这些字符时写成 `\x2C`、`\x22`、`\x60`、`\x3D`、`\x20`。生成器在拼好后会检查，不满足就拒绝生成。

每条正则 8.9–12.8 KB（词表压成前缀树，并在每组词前面加了“下一个字符在不在这些词的首字符里”的快速判断）。同一条正则在 Loon 里只定义一次（7 条）；mihomo 里用 YAML 的锚点 / 别名只写一次；Quantumult X 没有引用机制，26 个策略各写一遍。配置大小：Loon 55 → 126 KB，mihomo 71 → 139 KB，Quantumult X 51 → 326 KB，最长一行约 12.9 KB。

### 核对过什么（事实）

- Python：`tests/test_regions.py` 45 项。498 个人工写期望的节点名；CLDR 的 249 个国家 / 地区名与时区库的城市名（独立来源）；词表里每个词配 17 种前后缀写法（约 2.2 万个名字）；4 万个随机拼出的名字；“拼出来的正则”和“逐步判断”两种实现逐个对比；四个客户端产物里实际写出的筛选。
- ICU：`tools/check_icu.py`，Linux 上的 ICU 74（`libicui18n.so.74`）。7 条正则都能编译，2158 个节点名上的结果与 Python 完全一致、与手写期望完全一致；带本地补充样例（`tests/local_overlay_sample.yaml`，含指定节点名里的逗号、引号、等号、反引号）的那套正则同样一致。日志 `docs/evidence/icu-check.log`。
- mihomo 官方内核 v1.19.31：`tools/check_official.py`。`mihomo -t` 通过（含锚点 / 别名）；另外实际启动一次，订阅换成本地文件里的 2158 个假节点（不联网），从控制接口读出各地区组的成员，与手写期望、Python 结果完全一致；带本地补充样例的配置同样一致。日志 `docs/evidence/official-check.log`。
- 新旧对比：`docs/evidence/节点名称分组-新旧对比.md`。

### 没有验证的

- **Loon、Quantumult X 在 App 里的表现**：能不能导入这么长的正则、每行有没有长度限制、它们的引擎是否真是 ICU、iOS 上那一版 ICU 的行为、Quantumult X 的“自动”“负载均衡”策略是否按正则取节点。上一版（r6）的正则已经用了 `(?i)`、否定前瞻、否定后顾，同样没有在 App 里验证过；这一版新增的是 `\xHH`、嵌套的双重否定前瞻、后顾里的 `^`、字符类里的国旗字符范围（`[🇦-🇿]`，属于辅助平面字符），以及长度。
- **手机上的耗时**：只有估算。这台机器上几次运行，ICU 平均每次匹配 13–18 微秒（含调用开销），300 个节点时 Loon 约 30–40 毫秒、Quantumult X 约 100–140 毫秒；手机会慢几倍。
- **Clash Verge Rev、Clash Meta for Android 的界面层**读取带锚点 / 别名的配置：内核已验证，客户端自己的处理（合并、脚本）没有验证；锚点 / 别名是 YAML 标准写法。
- **真实订阅**：样本是我归纳和独立来源生成的，不是某家机场的真实节点名。真实订阅里的写法要用 `tools/check_node_names.py` 看。
