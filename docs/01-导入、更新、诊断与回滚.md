# 导入、更新、诊断与回滚

## 导入前

1. 对照 `docs/02-语法依据与能力矩阵.md` 里“已验证的版本”：验证过的只有 mihomo v1.19.31、sing-box v1.14.1 与 v1.12.0；你的客户端内置的内核版本如果更早，先在一台设备上试。
2. 把配置里的订阅占位链接换成你的订阅（或用 `build.py` 在本机生成 `dist/private/` 版本）。有 `source/local.yaml`（固定节点、公司内网等个人覆盖）时，要导入的是 `dist/private/` 里的那份：公开的 `dist/` 始终不含个人覆盖。
3. 先在一台设备上导入、按 `docs/05-验收记录.md` 的真机清单走一遍，再推广到其他设备。
4. 保留当前正在用的旧配置文件，出问题时直接切回（见“回滚”）。

**先导入、再在 App 里换订阅也可以**（2026-10-04 你问到的；菜单名字没有在真机上核对过，可能略有出入）。Loon、Quantumult X、Clash 系客户端的地区组都按节点名字从“所有订阅”里取节点，不认订阅叫什么，所以换地址或另加一条都行：

- Loon：导入后在“订阅节点”里把“订阅1”的地址换成你的；或者新加一条，再把占位的那条删掉。
- Quantumult X：“节点”→“引用（订阅）”里同样换掉或新加。
- Clash Verge Rev：导入配置文件后，右键这个配置 → 编辑文件，把 `proxy-providers` 下面那行 `url:` 换成你的订阅。不要把机场的订阅链接当成“配置”直接导入——那样用的是机场自己的规则，不是这一份。
- Clash Meta for Android：能不能在 App 里改文件内容没有确认；稳妥的做法是先用文本编辑器改好 `url:` 那一行再导入。
- SFA 不行：sing-box 不支持订阅，要先在电脑上生成（见下面“SFA”一段）。

换好订阅的文件含私密信息，不要发给别人，也不要写回 `source/`。

**从 GitHub 仓库取文件**（2026-10-05；仓库 `https://github.com/ixxooxo-alt/proxy` 是公开的）。先看清仓库里是哪一版：每份配置开头的注释里写着“统一源版本”，这一版是 `2026.10.05-2`；`dist/manifest.json` 里也有。写这份文档时仓库的 `main` 分支里是上一版 r10（`2026.10.05-1`，2026-10-05 晚推上去的）；这一版交付压缩包以后由我同样推到 `main`（`docs/06` 待决事项第 13 项）。文件的直接地址是：

```text
https://raw.githubusercontent.com/ixxooxo-alt/proxy/main/dist/loon/loon.conf
https://raw.githubusercontent.com/ixxooxo-alt/proxy/main/dist/quantumultx/quantumultx.conf
https://raw.githubusercontent.com/ixxooxo-alt/proxy/main/dist/mihomo/mihomo-profile.yaml
https://raw.githubusercontent.com/ixxooxo-alt/proxy/main/dist/mihomo/mihomo-core.yaml
```

注意三点：① 仓库里的是公开版，订阅是占位地址，下载后仍要换成你自己的；用这些地址重新导入新版时，App 里改过的订阅地址会不会被占位地址盖掉，取决于各 App 怎么处理“从地址导入配置”，没有在真机上核对——导入新版后先看订阅还在不在。② 换好订阅的文件、`dist/private/`、`source/local.yaml` 不要放进仓库：后两个已经写在 `.gitignore` 里，Git 会跳过；但从网页上手动上传文件不受 `.gitignore` 约束，要自己留意。③ `raw.githubusercontent.com` 在国内直连时常不通，App 里取不到时先开着旧配置的代理再导入，或者在电脑上下载好再传到手机。SFA 用不了公开模板，见下面“SFA”一段。

## 各客户端

**Loon（iPhone / iPad / Mac）**：导入 `loon.conf`。节点按 `[Remote Filter]` 里的名称正则分到地区（正则由词表生成，每个地区两条：`F-HK` 给手动组，`F-HK-AUTO` 给自动类的组；每条 12–16 KB，不要手改；见下面“节点按名称分地区”）；`[Proxy Group]` 每行末尾的 `img-url = …` 是策略组图标的地址（2026-10-05 起；只影响显示，见下面“策略组图标”）；
广告集合来自 `[Remote Rule]` 里的两条订阅（上游把这份列表拆成了两个文件，要一起用；导入后在“订阅规则”里确认两条都加载成功：带“域名”的那条应有三万七千多条规则，另一条约三百七十条；再用浏览器打开 `app-measurement.com`，应该打不开、请求记录里命中“广告拦截”——它只在带“域名”的那个文件里。见 `docs/09` 第 1 节；加载不出来时的换法见 `docs/06` 第 11 项）；本配置没有插件、复写、脚本和证书。需要可莉等第三方去广告插件时自行在 `[Plugin]` 添加，
插件规则的优先级介于本地规则和订阅规则之间（官方文档）。

**Quantumult X（iPhone / iPad / Mac）**：导入 `quantumultx.conf`。节点由 `server-tag-regex` 按名称分到地区（同上，由词表生成；它没有引用机制，26 个策略各写一遍，配置约 403 KB）；`[policy]` 每行末尾的 `img-url=…` 是策略组图标的地址；
广告集合在 `[filter_remote]`；`[mitm]` 为空，本配置不需要证书。

**Clash Verge Rev（Windows / macOS）** 与 **Clash Meta for Android**：导入 `mihomo-profile.yaml`。每个策略组的 `icon:` 是图标地址（显示不显示由客户端界面决定，没有核对）。
导入后请确认配置文件里的 `dns:` 这一段真的被用上了——本项目的 DNS 设计（国内外分开解析、局域网名字交给系统 DNS）全写在这一段里。Clash Verge Rev 的设置里有一个“DNS 覆写”开关：它打开时，界面里的 DNS 设置会盖掉配置文件里的。请让它保持关闭，再在 App 里查看实际交给内核的那份配置（运行时配置），`dns:` 下面应该有 `nameserver-policy`、`proxy-server-nameserver-policy` 这些行。这个开关近几个版本的行为有变动，我没有在 App 里验证，依据和链接在 `docs/06`“2026-10-05 审核（GPT r10）”一节；Clash Meta for Android 有没有类似的设置没有核对。
内核版本：本项目验证过的是 mihomo v1.19.31。r11 加的“局域网里的节点由系统 DNS 解析”用到 v1.19.20 才有的字段，内核更旧时这个字段会被忽略（配置照常加载，只是这一处修正不起作用；没有自建在局域网里的节点就没有影响）。内核版本在 App 的设置里能看到。
端口、TUN、控制面由客户端自己的设置决定，文件里不写。首次启动内核会从 jsDelivr 镜像下载 GeoSite / GeoIP 数据。
Windows 使用 TUN 需要客户端的服务模式，macOS 需要授权——这属于客户端设置，不在配置文件里。

**mihomo 内核直接运行**：用 `mihomo-core.yaml`。只监听本机（混合端口 7890、控制面 127.0.0.1:9090，未设 secret）。
如果要让局域网或远程访问控制面，必须先加 `secret` 并确认监听范围。TUN 默认关闭，开启需要权限。

**SFA（Android，sing-box）**：sing-box 不支持订阅，必须用 `build.py --singbox-sub-url` 或 `--singbox-nodes` 在本机生成
`dist/private/sing-box-1.14.json`（SFA 内核 1.14 及以上；在 v1.14.1 上验证）或 `sing-box-1.12.json`（兼容版；在 v1.12.0 上验证，1.13 没有单独验证），再以“本地配置”导入。
公开的 `dist/sing-box/*.json` 是没有节点的模板，所有代理组都指向“无可用节点”（拒绝连接），不能直接用。
首次启动要经“国外默认”下载规则集，所以节点必须先能用。

## 策略组图标（2026-10-05）

Loon、Quantumult X、Clash 系客户端的配置里，81 个策略组各带一个图标地址，指向你的图标仓库 `https://github.com/ixxooxo-alt/icon` 里 `256px/` 目录下和策略组同名的那张图；sing-box（SFA）没有图标字段。图标只影响显示，不影响分流。写法的依据和没有验证的地方见 `docs/02`“策略组图标”。

- **导入后先看两件事**：策略组是不是都还在（81 个；尤其是 Loon——它的图标地址写法只有社区用法作依据），图标有没有显示出来。图标没出来但策略组都在，多半是图片还没下载到（地址在 `raw.githubusercontent.com`，可能要等代理可用），不影响使用。
- **策略组少了、导入报错、或者你不想要图标**：把 `source/icons.yaml` 里的 `enabled: true` 改成 `false`，`python3 build.py` 重新生成，得到的是不带图标、其余逐字相同的配置。没有电脑时告诉我，我来出一份。
- **换图**：在图标仓库里用同样的文件名替换图片即可，配置不用动（客户端什么时候重新取图由它自己决定）。**改了文件名或删了图**，对应的组会没有图标；新加策略组时要先在图标仓库里放一张同名的图、在 `source/icons.yaml` 的 `available` 里登记，否则生成会报错。
- **核对图是不是都在**（需要电脑）：`git clone https://github.com/ixxooxo-alt/icon.git 图标目录`，然后 `python3 tools/check_icons.py --icon-repo 图标目录`。它不联网、不改图标仓库，逐个核对配置里写的地址在检出目录里有对应的 256×256 PNG。
- **换成 512px**：把 `icons.yaml` 的 `base_url` 里的 `256px` 改成 `512px` 重新生成。现在用 256px 的理由见 `docs/02`。

## 节点按名称分地区：怎么检查、怎么补

四个客户端用的是同一套规则，来自 `source/regions.yaml` 的词表（规则说明见 `docs/02`“节点名称分地区”）。它只看节点的名字，名字写错地区就会分错，也不证明节点实际从哪里出去。

**导入后先看一眼**：打开“香港·手动”“日本·手动”“美国·手动”等组，确认里面是对应地区的节点；再看“其他地区”，里面应该只有别的国家的节点和认不出名字的节点。然后看同一个地区的“自动”组：它的节点应该是“手动”组的一部分——名字说不清落地的节点只在手动组里，不进“自动 / 故障转移 / 负载均衡”，所以自动组比手动组少几个是正常的。说不清的有两类：名字指向不止一个地区（`日本-美国 01`）；名字里提到的地区不在落地位置——只写“地名 + 中转”（`香港中转 01`、`深港中转 01`、`HK-Relay-01`、`香港·中转·01`）、国旗后面直接接着中转词（`🇭🇰 中转 01`）、或者地区只出现在解锁说明里（`Premium 01 | 解锁美国`、`IEPL 01 🇺🇸解锁`）。国旗单独立在前面的 `🇭🇰 香港中转 01` 不算，它照常进自动组。后一类是这一版（2026-10-05）按审核意见从严、交付前我自己又补了几种写法的：**如果你的机场大多是“香港中转 01”这种写法，自动组会少很多甚至是空的**——这不是故障，但“手动优先”就没有自动兜底了，这时把节点名发给我（只要名字），或者按下面的办法在 `local.yaml` 里指定。自动组是空的而节点名又是普通写法（`香港 01`、`🇭🇰 HK-01`），才是不正常。**反过来也要看一眼**：“自动”组里有没有不该在的节点——规则只认识“中转、中继、转、入口、relay、transit、via、经”这几个词，换一种说法的中转节点（`经由日本 01`、`香港跳板 01`、`Singapore Entry 01`）会被当成落地放进自动组，而且检查工具不会把它们单独列出来（`docs/06` 最后一节有已知的 7 种写法）。看到了就把名字告诉我，或者先用下面的 `assign` 指定。发现下面任何一种情况都告诉我，并先切回上一份配置：导入时报正则错误；某个地区组是空的，而订阅里明明有这个地区的节点；所有节点都挤在“其他地区”；真节点哪个组里都找不到。

**在电脑上列出每个节点进了哪个组**（只需要节点名，不需要订阅链接，不联网）：

```bash
python3 tools/check_node_names.py 节点名.txt             # 每行一个节点名（从客户端的节点列表里抄下来或复制出来）
python3 tools/check_node_names.py --clash 订阅.yaml      # 或者给一份 Clash / mihomo 格式的订阅文件，只读其中的节点名
```

报告默认只列需要你看的：没认出地区的（进了“其他地区”）、说不清落地只进手动组的、按中转 / 让位规则判断的、被当成提示行不进任何组的、名字里有提示行常用的词但仍按节点处理的。开头一行是各组的数量，括号里是其中进自动类组的数量。加 `--all` 列出全部。用 `build.py --singbox-nodes / --singbox-sub-url` 生成 sing-box 配置时，同样的报告会自动写到 `dist/private/节点分组报告.txt`。

没有电脑、只用手机时：把节点列表截图或把节点名发给我（只要名字，不要订阅链接），我来跑这份报告。

**某个节点没认出来或分错了**：复制 `source/local.example.yaml` 为 `source/local.yaml`，在 `node_names` 里补，然后 `python3 build.py`，导入 `dist/private/` 里的配置（本地补充只进私密产物，公开的 `dist/` 不变）：

```yaml
node_names:
  extra_words:
    us: {words: [圣路易], latin: [STL]}       # 给美国补一个中文词、一个英文代码；地区 id：hk jp kr tw sg us，其他国家写 other
  assign:
    - {name: "Premium 01", region: jp}        # 名字里完全看不出地区的，直接指定（写完整节点名）；region 写 none 表示哪个组都不进
    - {name: "日本-美国 01", region: jp}      # 说不清落地、只进了手动组的节点：指定以后，这个地区的手动组和自动类组都进
    - {name: "香港中转 01", region: hk}       # 只写“地名 + 中转”的节点同理：你确定它落在香港，就指定
```

如果这个写法很多机场都在用，告诉我，我把它加进统一源的词表。

## 用官方工具自检（强烈建议）

```bash
mihomo -t -d . -f mihomo-core.yaml              # mihomo 官方解析检查
sing-box check -c dist/private/sing-box-1.14.json
```

也可以用 `tools/check_official.py` 一次检查全部公开模板和一份带样例节点的 sing-box 配置（官方程序从各项目 GitHub Releases 下载，核对发布页的 SHA-256）。注意 `sing-box check` 只做解析和初始化，不执行完整启动，通过也不等于运行时一定正常。

**用官方内核和真实的上游数据核对“这个域名交给谁”**（2026-10-04 新增；上游数据每天在变，建议隔一段时间、或者发现某个网站走错组时重跑）：

```bash
# 准备：官方 mihomo、sing-box 可执行文件；MetaCubeX/meta-rules-dat 发布的 geosite.dat、geoip.dat、geoip.metadb（放一个目录）；
#       SagerNet/sing-geosite、sing-geoip 的 rule-set 分支里的 geosite-category-ads-all.srs、geosite-cn.srs、
#       geosite-geolocation-!cn.srs、geoip-cn.srs（放一个目录）；blackmatrix7/ios_rule_script 的检出目录
python3 tools/check_real_routes.py --mihomo <mihomo> --singbox <sing-box 1.14> --singbox-112 <sing-box 1.12> \
    --geodata-dir <目录> --srs-dir <目录> --bm7 <目录>
```

它不联网、不开 TUN、不动系统代理：规则原样，所有出口换成拒绝，只在 127.0.0.1 上开临时端口，逐个目标发起连接后从内核日志读出命中的规则。2026-10-05 起它另外核对拨号时把名字交给哪个 DNS 服务器（节点服务器的名字、域名形式的直连目标；这一项保留真实的拨号，DNS 换成本机替身，一律答 127.0.0.1）：先有 sing-box 的（`docs/03`“sing-box：拨号时的解析不看 DNS 规则”），r11 起 mihomo 也有，并且多核对几条设备发来的 DNS 查询（`docs/03` 最后一节）。结果和人工写的期望不一致时会列出来——例如某个本该走代理组的域名被上游收进了国内集合。`tests/cases.yaml` 的 `upstream_followed` 一节记的是反过来的情况：上游数据是这样、决定不更正的已知行为（现在只有 mihomo 上的整段 `.ms`，`docs/06`）；上游改掉以后它会在这里报不一致，按提示把那一条和 `docs/06` 的对应说明删掉。加 `--write-snapshot` 会把这次的成员关系记进 `tests/data/real_sets.json`（自动测试用它重放）。把这些路径写进环境变量后，`bash tools/run_checks.sh` 会把这一步和别的检查一起跑（变量名见脚本开头的注释）。

Loon、Quantumult X 没有命令行检查工具，只能导入 App 看是否报错。它们的节点筛选正则另用 `python3 tools/check_icu.py` 在 ICU 正则引擎上跑过一遍（推断这两个 App 用的是苹果系统自带的、基于 ICU 的正则），这不等于在 App 里验证过。

## 诊断：某个网站走了哪个组

- mihomo（Clash Verge Rev / CMFA）：连接面板里能看到命中的规则和代理链。
- sing-box：把 `log.level` 临时改成 `debug`，日志会打印命中的规则。
- Loon / Quantumult X：最近请求 / 日志里能看到命中的策略。

对照 `docs/04-规则清单与证据.md` 查这个域名应该归哪个组；不一致时先看“已知限制”里是否是各端语义差异。
mihomo 系客户端可以把连接记录交给 `tools/check_connections.py` 自动对照（采集方法见 `docs/09-真机验收操作清单.md` 第 6 节）。
查出口 IP 的网站只能说明“它自己”走了哪个出口，不能证明其他业务走同一出口。

## 更新

1. 改 `source/`（或更新到新的统一源版本）→ `python3 build.py` → `python3 -m unittest discover -s tests`（或 `bash tools/run_checks.sh`，任何一步失败都会以非零退出码结束）。
2. 生成是“全部成功才替换”：统一源校验、私密产物（订阅下载、节点转换）、写盘前的结构检查，任何一步失败都不改动现有产物；写入时先把所有文件写成临时文件，再逐个替换，替换中途出错会把已替换的恢复成旧版本。进程被强行终止或断电时，目录里可能留下 `.new-*` / `.bak-*` 文件，按文件名手动恢复或删除即可。
3. `dist/manifest.json` 记录统一源版本、源码摘要（含 `build.py`，不含 `local.yaml`）和每个产物的 SHA-256；`python3 build.py --check` 会连 manifest 一起核对。私密产物另有 `dist/private/manifest.json`，另外记录 `local.yaml` 的摘要。
4. 组名保持不变时，客户端会保留你的手动选择；改组名会让该组回到首次默认值。
5. 远程集合（广告、GeoSite / GeoIP）由客户端按自己的周期更新，内容以上游为准，不在本项目版本里（2026-09-30 你决定不锁定版本、跟随上游）。所以同一份配置在不同日期的匹配结果可能不同，排查时先确认远程集合的更新时间。

## 回滚

- 设备上：重新导入上一份配置文件（导入前务必留一份）。地区筛选正则在 2026.09.30-1（r6）是每条几百字节，2026.10.02-1（r7）约 10 KB，r8、r9（2026.10.04-1、2026.10.04-2）、r10（2026.10.05-1）和这一版（2026.10.05-2，r11）都是 12–16 KB、每个地区两条，r10 起每个策略组另外多了一个图标地址（r11 的 Loon、Quantumult X 配置和 r10 相比只有开头注释里的版本号不同）；哪一版都还没有在 Loon / Quantumult X 上验证过（r6 的短正则也没有，只是写法简单得多）；这两个 App 导入后如果报正则错误、地区组为空或明显变卡，先切回 r6（2026.09.30-1）的配置，再把现象告诉我；如果只是策略组少了或图标有问题，先试不带图标的同一版（上面“策略组图标”一节）。注意 r6、r7 的 Loon 配置只订阅了广告列表的一半（`docs/06`“2026-10-04”一节），切回去以后 Loon 上的广告拦截会比这一版弱。
