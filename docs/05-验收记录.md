  - 可移植性：正则里没有逗号、双引号、反引号、等号、空格；没有用肯定前瞻、`\b`、`\d`、`\w`、`{n}` 等；每条不超过 16,000 字节；有 ICU 的机器上实际用 ICU 跑一遍；长名字不会让匹配时间失控（在带超时的子进程里跑）。
  - 词表写错会被拒绝（同一个词在两个地区、纯英文词放错位置、带等号的正则片段、未知字段、YAML 把 `NO` 读成布尔值、两个让位地区等 8 类）；`local.yaml` 的补充只影响私密产物，写错同样被拒绝；检查工具的报告只含节点名称。
- 旧的节点名称样例（`tests/cases.yaml` 的 28 个，含提示行、三字母地区码、易混词如 Russia / Australia）仍然保留并通过。
- Clash → sing-box 节点转换：6 种协议的字段映射、TLS 不被放宽、不支持的协议 / 参数被报告而不是静默处理。
- 跨平台：输出目录与项目跨盘符时生成不失败；统一源摘要不受系统路径分隔符影响。
- 连接记录分析工具（`tools/check_connections.py`）：能解析 mihomo `/logs`、`/connections` 的输出和从客户端复制的日志文本；分类正确（符合统一源、不一致、上游广告集合误拦、国外 / 国内兜底）；报告不含来源地址；用模拟器按生成的 mihomo 配置路由全部用例，工具的判断与配置一致。

## 推断（有依据，但没有运行验证）

- mihomo 的“手动优先”：源码显示 fallback 组选第一个健康成员，成员是组时对其当前选择做检查，连续连接失败会触发检查；因此手选节点失效后会切到同地区自动组，恢复后切回。
- mihomo 筛选为空时默认落到 COMPATIBLE（源码中是直连出站），因此设了 `empty-fallback: REJECT`。
- Loon 规则优先级（本地 > 插件 > 订阅；域名先于 IP）来自官方文档；Quantumult X 的优先级来自社区文档。
- 各端字段语法见 `docs/02-语法依据与能力矩阵.md`。
- **Loon、Quantumult X 的节点筛选正则由 ICU 执行**：两者是苹果平台的原生应用，推断用的是系统自带的 `NSRegularExpression`（底层是 ICU）。官方没有说明；旁证是官方与社区示例里的写法 ICU 都支持。所以“在 ICU 上结果一致”只能推出“在这两个 App 里大概率一致”。
- **mihomo 用真实订阅时走的路径与检查时相同**：检查用的是本地文件订阅，真实使用是 http 订阅；两者取到节点后都由 `GroupBase.GetProxies` 用同一条 `filter` 筛（源码）。另外，组的测速地址和订阅上的相同时，mihomo 不会把组的 `filter` 再拼进健康检查（源码 `healthcheck.go` 的 `registerHealthCheckTask`：`url == hc.url` 时直接返回），本项目两处用的是同一个地址。

## 未验证

- **官方解析器的边界**：mihomo `-t` 与 sing-box `check` 已对公开配置和样例节点配置运行（见上表），但没有用你的真实订阅运行；`sing-box check` 只做解析和初始化，不执行完整启动。“用官方内核核对路由”那一项实际启动了内核，但出口全部换成了拒绝、不开 TUN、不联网，验证的是“规则把连接交给谁”，不是连通性。
- **其他版本的内核**：只在 mihomo v1.19.31、sing-box v1.14.1 与 v1.12.0 上跑过；Clash Verge Rev、Clash Meta for Android、SFA 内置的内核版本没有核对，sing-box 1.13 没有单独运行。
- **Loon、Quantumult X**：没有命令行工具，也没有设备，未导入。
- **Loon、Quantumult X 上的节点分组**（最要紧的未验证项，这一版风险比 r7 更大）：每条 12–16 KB 的筛选正则（Loon 13 条，Quantumult X 26 个策略各写一遍，配置 240 KB / 403 KB）能否导入、分组结果是否和预期一致、策略页是否变卡，都没有在 App 里看过。Quantumult X 的“自动”“负载均衡”策略是否按 `server-tag-regex` 取节点，官方 sample.conf 自相矛盾，也没有验证。
- **策略组图标**（2026-10-05）：Loon、Quantumult X、Clash Verge Rev、Clash Meta for Android 里显示不显示，Loon 接不接受 `img-url` 后面写图片地址（依据只有官方示例里的参数名和社区配置的写法），图片从 `raw.githubusercontent.com` 下载得到下载不到，都没有在真机上看过。已核对的只是“地址写得对、图在图标仓库里”。
- **sing-box 的拨号解析**：用官方内核在本机核对过“名字被拿去问哪个 DNS 服务器”，没有在真实网络、真实节点、TUN 接管下看过；SFA 里“系统 DNS”实际是哪一个没有核对。
- **Loon 的第二个广告列表文件**（`AdvertisingLite_Domain.list`，每行一个域名）能否被 Loon 当作订阅规则解析：官方文档没有写这种格式，依据只有上游规则库的说明。
- **Loon / Quantumult X 的路由**：没有能在电脑上运行的官方内核，这两端的“真实数据核对”用的是自制模拟器（规则优先级按官方 / 社区文档实现），不是 App 本身。
- **真实网络下的 DNS**：sing-box 的 DNS 去向是在本机用假 DNS 服务器核对的（看查询被交给哪个服务器），没有在真实网络里观测解析结果；Loon / Quantumult X 上未分类域名解析到国内 IP 的实际比例没有观测。
- **Qwen 国际版实际使用的主机**：只按上游列表收了 `qwen.ai`、`qwenlm.ai`，没有抓过它的实际连接。
- **手机上筛选节点的耗时**：只有按这台机器估算的数（300 个节点：Loon 约 36–38 毫秒，Quantumult X 约 63–66 毫秒，2026-10-05 几次运行的范围；手机会慢几倍）。
- **Clash Verge Rev、Clash Meta for Android 的界面层**读取带 YAML 锚点 / 别名的配置：内核已验证，客户端自己的处理没有验证。
- **真实订阅的节点名**：分组规则只用归纳的样本、审核方构造的反例和独立来源的国家 / 城市名检验过，没有用任何一家机场的真实节点名检验。这一版把“地名 + 中转”“国旗 + 中转”“只在解锁说明里提到地区”的节点从自动类的组里拿掉了：你的机场有多少节点是这种写法、自动组会少多少，要看真实的节点名才知道。反过来，规则不认识的中转说法（`经由`、`跳板`、`Entry` 等，`docs/06`）在真实订阅里有多少，也要看了才知道。
- **`tools/check_icu.py` 在 Windows、macOS 上**：只在 Linux 上跑过；另两个平台找不到或加载不了 ICU 时会报告“没有做检查”（那一项测试自动跳过）。
- **所有真机行为**：接管范围、DNS、IPv6、故障切换时长、选择保持、广告效果、解锁、实际出口，全部未测。
- **规则归属的实际效果**：社区来源已对照固定快照，但那只说明上游维护者也这样归类；21 条维护者知识、5 条“需求指定”、9 条“从另一版导入”的广告没有同值的外部佐证。见 `docs/06-已知限制与待决事项.md` 的“证据强度”。
