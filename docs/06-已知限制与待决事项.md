- **上游广告条目连带的影响**：跟随上游拦截的 `analytics.google.com` 同时是 Google Analytics 后台网页；`graph-fallback.instagram.com`、`graph.whatsapp.*` 被上游标为统计上报，我没有找到它们承担正常功能的官方依据，仍然拦截。`graph.instagram.com` 原来也在这里，审核指出它是 Instagram 官方 API 主机（发消息等），2026-09-30 改为误杀例外，四端都放行、归 Meta 社交。需要 GA 后台或遇到相关功能异常时，先从 `source/adblock.yaml` 的 `local_ads` / `local_tracking` 删掉对应条目，再在 `exceptions` 里加上它，然后重新生成（只加例外会被生成器拒绝：例外和自有拦截不能重叠）。
- **Loon 的“手动优先”**：官方示例说 url-test / fallback 只支持节点、其他会被忽略，现行文档又说策略组支持嵌套。为此 Loon 的手动优先组在两个成员组后附带同地区节点：嵌套生效时是真正的“手动优先 → 自动兜底”；嵌套被忽略时退化为同地区顺序故障转移（不跨国、不直连）。实际是哪种，要在设备上看该组的成员列表确认。
- **Quantumult X 没有 no-resolve**：标准版里，域名连接走到 Telegram 专属 IP 规则时会先解析。严格版里域名兜底先接住全部带点的域名，走不到 IP 规则，没有这个差异（`docs/03`“Loon / Quantumult X：严格版”一节）。
- **Quantumult X 的策略名**：`Apple Music/TV`、`Disney+`、`Google AI`、`Apple AI`、`PayPal·美国固定` 等含 `/`、`+`、空格、`·`，官方没有说明是否支持，需真机确认；不支持时只给 QX 换名。
- **Loon / Quantumult X 没有引入国内 / 国外域名大集合**：它们含宽泛关键词规则（例如 `DOMAIN-KEYWORD,jav`、`DOMAIN-SUFFIX,ms`），不符合收录要求。代价是没有命中域名规则的境外域名要先由国内 DNS 解析：国内 DNS 看得到这些域名；解析结果不是国内 IP 时走国外默认，**是国内 IP 时会直连**（境外网站用了国内 CDN 节点、解析被污染到国内地址等情况）。以前这里写的是“结果仍走国外默认”，少了这个条件（2026-10-03 审核 F06），完整说明见 `docs/03`“已知取舍”第一条。**这一条说的是标准版**；2026-10-06 起另有严格版，用的是只含域名和后缀的国内域名清单（不含关键词规则），见下面“2026-10-06（r12）”一节。
- **广告数据源各端不同**：mihomo / sing-box 用 domain-list-community 的 `category-ads-all`（真实文件里 911 条），Loon / QX 用 blackmatrix7 的 `AdvertisingLite`（2025-12-08 更新；域名 37,692 条、关键词 187 条、IP 段 187 条）。两者覆盖范围不同：同一个广告主机可能在这两端被拦、在另两端不被拦，反过来也有。`tests/cases.yaml` 里有 6 个用真实广告列表核对的用例，其中 4 个在两类客户端上结果不同（`ads.yahoo.com`、`ads.viber.com`、`t.appsflyer.com`、`user.wixsite.com`），按各端分别写了期望。Loon 版分成两个文件，见下面“2026-10-04”一节。
- **sing-box**：没有故障转移 / 负载均衡组、不能隐藏子组、不支持订阅；广告拦截是规则动作，不能在界面一键关闭；首次启动要经“国外默认”下载规则集，节点必须可用；空组用的 `block` 占位出站在 1.14 已标记弃用（v1.14.1 源码中仍可用），节点转换报告会列出哪些组没有节点；排期：1.16 发布前复查，若被移除，改为生成时去掉空组并在报告中列出受影响的默认出口。不返回 AAAA 时 fakeip 不配置 IPv6 段。
- **mihomo 旧内核**会忽略 `empty-fallback`，筛选为空的组会落到 COMPATIBLE（等同直连）。官方 wiki 已记载该字段但没有写起始版本，我也没有查证；验证过的版本只有 v1.19.31（`docs/02`“已验证的版本与依据”），请用这个版本或更新的内核，更早的版本不要假定可用。

## 2026-09-30 审核（Astra r5）后的修改与仍然存在的限制

- **README 对“手动优先”的描述已收窄**：mihomo 按设计实现；Loon 的嵌套、Quantumult X 的恢复切回、各端的切换时限，都要真机确认。

## 2026-10-05 审核（GPT r9）后的修改与仍然存在的限制

逐条核实与处理见 `docs/08-外部审核记录.md` 第 5 轮。和使用直接相关的：

- **自动类的组更严了**（F01）：名字里提到的地区词都不在落地位置的节点——只写“地名 + 中转 / 入口 / relay”、地区只出现在“解锁”说明里、地名在箭头前面或 `via` / `经` 后面——以前只要名字里只有这一个地区就进它的自动 / 故障转移 / 负载均衡，现在只进手动组。出错的方向从“可能把出口不在这个国家的节点放进自动组”变成“自动组里可能少几个其实没问题的节点”。代价和可选的做法见上面“需要你决定的事项”第 12 项。
- **连接符不再影响结果**（这一条是我自己发现的，不是审核意见）：地名和“中转”这类词之间隔着空格、连字符、下划线，现在同等对待。以前只认空格，`香港 中转 01` 和 `香港-中转-01` 的结果不一样。顺带的变化：`日本-中转-美国-01`、`日本_转_美国_01` 以前两个地区都算（只进手动组），现在按“日本中转、美国落地”归美国。竖线和括号仍然另起一段：`香港 01 | 中转`、`香港 01 [中转]`、`中转 香港 01` 里地名在落地位置，手动、自动都进。
- **交付前自查又补了四处**（也不是审核意见；是我在交付之前拿没见过的写法把 F01 这一类问题自己查了一遍，`docs/08` 第 5 轮“交付前自查”）。改之前，下面这些名字都会进自动类的组：
  - 国旗后面直接接着中转词或“解锁”：`🇯🇵中转 01`、`IEPL 01 🇺🇸解锁`；`香港 01 | 🇺🇸解锁` 更是进了美国的自动组。现在国旗和文字用同一套“落地位置”的条件。连带的变化：国旗不在落地位置时，节点进这面国旗所属地区的手动组（以前掉进“其他地区”，例如 `Premium 01 | 解锁🇺🇸`）；`🇯🇵转🇭🇰 01` 归香港（以前因为香港让位归日本）。
  - `经香港 01`、`港日中转 01`：单个字的“港”在“香港”“港日”里被单独算了一次。后一个以前只进香港、进不了日本的手动组，现在进日本的手动组。
  - `via-HK-01`、`日本-解锁-01`：`via` / `经` 后面、“解锁”前面以前只认空格。`香港 01 美国-解锁` 以前进美国的自动组，现在归香港。
  - `香港·中转·01`、`香港/中转/01`、`HK.Relay.01`、`香港—中转—01`：间隔号、斜杠、句点、破折号现在也算连接符。
- **仍然认不出的中转写法**（自查时试出来、没有改的；它们**会进自动类的组**）：规则只认识 `中转`、`中继`、`转`、`入口`、`relay`、`transit` 和 `via`、`经` 这几个词，换一种说法就当成落地了。已经记下来的 7 种见本页最后一节的第二张表。没有为它们扩充词表，原因有两个：这些是我自己想出来的写法，不是从真实订阅里看到的；每多认一种，13 条正则都要变长，而正则长度本身就是 Loon / Quantumult X 上最大的未知数。你的订阅里如果有这类写法，检查工具不会把它们单独列出来（它认为这些就是落地）——要靠你看一眼各地区“自动”组里有没有不该在的节点，把写法告诉我。
- **正则又长了一些**：自查改完以后，13 条筛选正则合计长了约 6%（每条多 0.6–1.0 KB），最长的一条从 15.1 KB 到 15.7 KB，和 r9 最长的那条（15.7 KB）差不多；测试里 16,000 字节的上限只剩约 300 字节的余量。这个上限是本项目自己定的，用来防止正则不知不觉越长越大，不是 Loon / Quantumult X 公布的限制：超过它只是测试失败，不代表 App 一定拒绝；低于它也不保证 App 接受（2026-10-05 审核 r10 提醒要说清楚）。Loon / Quantumult X 能不能接受这么长的正则本来就没有在真机上验证过（本页最后一节第二条），这次是往不利的方向加了一点。
- **sing-box：局域网里的名字不再拿去问公共 DNS**（F02；只影响 SFA）：节点的服务器地址如果是 `gateway.lan`、`proxy.home.arpa` 这类名字或不带点的主机名，现在由系统 DNS 解析；域名形式的局域网目标在直连之前也先由系统 DNS 解析。公网域名的节点、直连的公网域名照旧由国内 DNS 解析，没有变。仍然存在的限制：公司自定义的内网域名（不在 `lan`、`local`、`localdomain`、`home.arpa`、`localhost` 之下）没有覆盖，要把后缀加进 `source/project.yaml` 的 `lan.domain_suffix`；只在本机用官方内核核对过，没有在真实网络和真机上看过（`docs/03`“sing-box：拨号时的解析不看 DNS 规则”一节）。
- **不带点的主机名作为访问目标**（`http://nas/`；核对上一条时顺带看的。规则 r10 没有动，以前的版本同样如此，不是 r10 引入的；r11 也没有动，只是查清了 mihomo 上 DNS 那一半的去向，见下一节）：没有专门的规则，原样到达内核时会被交给国外默认，打不开。平常不容易遇到，原因和绕开的办法见 `docs/03`“已知取舍”。没有改：各端的写法不一样，Quantumult X 没有能表达“不带点”的规则类型，要做的话先定范围。

- **策略组图标**：只影响显示。Loon 的写法依据最弱（`docs/02`“策略组图标”），三个客户端里都没有在真机上看过；图片在 `raw.githubusercontent.com`，国内直连时常不通，图标可能要等代理可用以后才出来。导入后策略组少了或报错，先换成不带图标的同一版（`docs/01`“策略组图标”）。图标仓库是你的，本工程不含图片。
- **GitHub 仓库**：仓库是公开的，所有人都能看到里面的全部文件，包括 `docs/00-需求原文.md` 里你的原话和各轮审核报告的副本。带订阅的 `dist/private/`、个人覆盖 `source/local.yaml` 已写进 `.gitignore`（有测试检查 Git 确实会跳过它们）；但 `.gitignore` 管不到网页上的手动上传，也管不到你自己改过订阅的配置文件——那些不要放进去。仓库里是哪一版、怎么确认，见上面第 13 项。
- **r10 的检查是在重建后的环境里跑的**（r11 沿用这个环境）：r10 做到交付前复查时原来的云端工作环境被换掉了，工程是按操作记录从 r5 的交付包逐步重做出来的（每一轮的摘要、产物、测试项数都和当时的记录对得上），全部检查在新环境里重跑。运行环境、核对用的上游数据文件、独立来源的地名数据和前几轮记录的不是同一份，细节见 `docs/05`“已验证的事实”开头。

## 2026-10-07（r13）：处理 GPT 对 r12 的审核时新写明的限制

逐条的核实与处理见 `docs/08-外部审核记录.md` 第 8 轮。**这一版的配置与 r12 逐字节相同**，下面几条都是原来就有的情况，这一轮核实时才查清或写准，没有哪一条是这一轮引入的。

- **“系统 DNS”不一定是你家路由器**（GPT 第 11 点提醒；我读 mihomo v1.19.31 的源码查清的，没有在真实系统上验证）。Clash 系的配置把局域网里的名字（`nas.lan` 这类访问目标、服务器是局域网名字的节点）交给 `system`。内核从系统设置里读 DNS：Windows 读网卡上设的，macOS 读 `/etc/resolv.conf`，Clash Meta for Android 由 App 告诉它；读不到时这次解析失败，不会改问别的服务器（**更正**：r13 这里写的是“读不到时用内置的 114.114.114.114 和 8.8.8.8”，读错了源码——那两个地址只属于内核另建的一个全局解析器，配置里写的 `system` 不带这个兜底；GPT 审核 r13 的 R13-F02，见下面 r14 一节）。两种情况下它不是路由器：
  - **Mac 上开着 Clash Verge Rev 的虚拟网卡**：App 把系统 DNS 改成了 114.114.114.114，内核的“系统 DNS”也就是它。按源码推断，这时用名字访问局域网设备、用局域网名字的节点都会解析不到，这些名字也会被发给这个公共 DNS。
  - **Windows 上照 `docs/01` 的那句建议，不开严格路由、把网卡的 DNS 改成公网地址**：同上。
  用 IP 地址访问不受影响；机场订阅的节点不受影响。怎么看：`docs/09` 第 1 节“局域网”一行。配置文件里改不了（不知道你家路由器的地址），遇到了告诉我再商量办法（`docs/03`“客户端这一侧”）。

## 节点按名称分地区：做法与限制（2026-10-02；2026-10-04、2026-10-05 更新）

规则、依据和核对结果见 `docs/02`“节点名称分地区”；怎么检查、怎么补见 `docs/01`。和使用直接相关的：

- **只看名字**：判断的是“名字写的是哪里”，不是节点实际从哪里出去。机场把名字写错、或者同一个名字换了落地，这里发现不了；实际出口仍要实测登记（`docs/05`）。所以“自动 / 故障转移 / 负载均衡只在同一个地区里切换”说的是“只在名字指向这个地区的节点里切换”，不是出口地理位置的保证。
- **Loon、Quantumult X 上没有验证过**（最要紧的一条）：地区筛选正则在 r6 是每条几百字节，r7 约 10 KB，r8 起各版（含这一版）都是 12–16 KB，而且每个地区从一条变成两条（Loon 配置 r6 → r7 → r9 → r10 和这一版：55 → 126 → 240 → 240 KB；Quantumult X 51 → 326 → 430 → 403 KB，因为它没有引用机制，26 个策略各写一遍；最长的一行约 15.8 KB）。r10 起每个策略组的行尾还多了一个图标地址。这些正则在 ICU 正则引擎上跑过、结果与期望一致，但“这两个 App 用的是 ICU”是推断，App 自己对一行的长度、对这些写法有没有限制也不知道。导入后请先按 `docs/09` 第 1 节看地区组里的节点对不对；有问题先切回 r6 的配置（统一源 2026.09.30-1，短正则），再告诉我现象。如果确认是正则太长造成的，光删少用的城市帮助有限（r7 时试过：把美国和其他国家的词表都砍到只剩几个，每条仍有 3–5 KB，因为国旗、中转这些判断本身就占一半）；那时需要给这两个 App 另出一套短写法（只做“名字里有这些词”的简单匹配，不处理中转和解锁说明），这一版没有做——审核方的意见也是“没有必要在尚未发现实际问题时全面改写”。
- **Quantumult X 的“自动”“负载均衡”**：官方 `sample.conf` 的注释说 `server-tag-regex` 只对 static、available、round-robin 三种策略生效，同一文件的示例又把它写在 dest-hash 和 url-latency-benchmark 上。本项目的“X·自动”用 url-latency-benchmark、“X·负载均衡”用 dest-hash（一直是这样）。如果注释是对的，这两个组里不会按地区取到节点。要在设备上看这两个组的成员确认；确认不生效时，这两种模式在 Quantumult X 上需要换实现或去掉。
- **说不清落地的名字只进手动组**（2026-10-04，你的决定）：例如 `日本-美国 01`、`🇯🇵 Tokyo 01 🇺🇸`、`美国 奥克兰 01`、`香港-东京 01`；2026-10-05 起还包括名字里提到的地区不在落地位置的——`日本中转 01`、`香港-中转-01`、`IEPL 01 Unlock US`、`Premium 01 | 解锁美国`（审核 r9 的 F01；上表第 12 项），以及自查补的 `🇯🇵中转 01`、`IEPL 01 🇺🇸解锁`、`香港·中转·01`、`via-HK-01`、`经香港 01`、`港日中转 01`。它们在所列地区的“手动”组里都能选到，但不进任何地区的“自动 / 故障转移 / 负载均衡”。代价：如果你的机场大量用这类写法，自动组里的节点会比手动组少——检查工具会把它们列在“说不清落地，只进手动组”里，确定落地的在 `local.yaml` 的 `node_names.assign` 里指定，指定后两边都进。
- **香港让位是一个取舍**：`香港-日本 01`、`深港专线 东京 01`、`港美 IEPL` 归对方，因为香港在这类名字里多半是中转。三种情况会分错或说不清：先写落地、后写入口又不带“中转”字样（落地香港的 `日本-香港 01` 会归日本）；名字里是“香港 / HK”加别的地区的城市（`香港-东京 01`、`HK-Tokyo 01`）——城市词也可能只是宣传语里的字眼（`香港 01 纽约时报`），所以这种一律按说不清处理，两边都只进手动组；宣传语里带着别的地区的国旗、又没有“解锁”字样（`🇭🇰 香港 01 | NF 🇺🇸`）——两面旗都在落地位置，香港让位，归美国，手动、自动都进。这种名字用 `assign` 指定。
