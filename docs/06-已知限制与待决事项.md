## 各端语义差异（生成器已按各端处理，但结果不完全一致）

- **Loon / Quantumult X 的广告集合优先级低于本地产品规则**（Loon 官方：本地 > 插件 > 订阅）。domain-list-community 快照里落在产品规则范围内的 30 个广告条目，已全部前置：28 条放进自有拦截（四端都拦），2 条按 GitHub 官方放行清单放进误杀例外（四端都不拦）。仍有差异的是只出现在 blackmatrix7 广告集合里、又位于产品根域下的主机（例如某个 `*.twimg.com` 统计域名）：这两端会走产品组而不是被拦截。mihomo / sing-box 严格按“例外 → 拦截 → 产品规则”执行。
- **上游广告条目连带的影响**：跟随上游拦截的 `analytics.google.com` 同时是 Google Analytics 后台网页；`graph-fallback.instagram.com`、`graph.whatsapp.*` 被上游标为统计上报，我没有找到它们承担正常功能的官方依据，仍然拦截。`graph.instagram.com` 原来也在这里，审核指出它是 Instagram 官方 API 主机（发消息等），2026-09-30 改为误杀例外，四端都放行、归 Meta 社交。需要 GA 后台或遇到相关功能异常时，先从 `source/adblock.yaml` 的 `local_ads` / `local_tracking` 删掉对应条目，再在 `exceptions` 里加上它，然后重新生成（只加例外会被生成器拒绝：例外和自有拦截不能重叠）。
- **Loon 的“手动优先”**：官方示例说 url-test / fallback 只支持节点、其他会被忽略，现行文档又说策略组支持嵌套。为此 Loon 的手动优先组在两个成员组后附带同地区节点：嵌套生效时是真正的“手动优先 → 自动兜底”；嵌套被忽略时退化为同地区顺序故障转移（不跨国、不直连）。实际是哪种，要在设备上看该组的成员列表确认。
- **Quantumult X 没有 no-resolve**：域名连接走到 Telegram 专属 IP 规则时会先解析。
- **Quantumult X 的策略名**：`Apple Music/TV`、`Disney+`、`Google AI`、`Apple AI`、`PayPal·美国固定` 等含 `/`、`+`、空格、`·`，官方没有说明是否支持，需真机确认；不支持时只给 QX 换名。
- **Loon / Quantumult X 没有引入国内 / 国外域名大集合**：它们含宽泛关键词规则（例如 `DOMAIN-KEYWORD,jav`、`DOMAIN-SUFFIX,ms`），不符合收录要求。代价是未命中规则的境外域名会被国内 DNS 看到（结果仍走国外默认）。
- **广告数据源各端不同**：mihomo / sing-box 用 domain-list-community 的 `category-ads-all`，Loon / QX 用 blackmatrix7 的 `AdvertisingLite`（38,068 / 38,066 条，2025-12-08 更新）。两者覆盖范围不同。
- **sing-box**：没有故障转移 / 负载均衡组、不能隐藏子组、不支持订阅；广告拦截是规则动作，不能在界面一键关闭；首次启动要经“国外默认”下载规则集，节点必须可用；空组用的 `block` 占位出站在 1.14 已标记弃用（v1.14.1 源码中仍可用），节点转换报告会列出哪些组没有节点；排期：1.16 发布前复查，若被移除，改为生成时去掉空组并在报告中列出受影响的默认出口。不返回 AAAA 时 fakeip 不配置 IPv6 段。
- **mihomo 旧内核**会忽略 `empty-fallback`，筛选为空的组会落到 COMPATIBLE（等同直连）。官方 wiki 已记载该字段但没有写起始版本；请使用较新的 v1.19.x。

## 2026-09-30 审核（Astra r5）后的修改与仍然存在的限制

逐条核实与处理见 `docs/08-外部审核记录.md` 第 3 轮。和使用直接相关的：

- **Clash（mihomo）的局域网名字**：以前 `nas.lan` 这类只有路由器认识的名字会被发给公共 DoH，解析不到；现在四端都把局域网后缀交给系统 DNS。公司自定义的内网域名还不能在统一源里指定解析服务器（见 `docs/03`）。
- **sing-box 节点转换**（只影响 SFA 的私密配置）：现在会报告并跳过这些节点——缺少必填字段（密码、UUID 等）、没开 UDP 的 AnyTLS（sing-box 无法禁止它转发 UDP）、带 sing-box 无法表达的插件参数（额外请求头、证书固定等）、HTTP Upgrade 同时带 early data。与策略组同名的节点（例如就叫“日本”）会改名为“日本（节点）”并写进报告，地区筛选和固定节点仍按原名匹配。v2ray-plugin 的 mux 与 Host、obfs 的 Host、WebSocket 路径里的 `?ed=` 都按 mihomo 的含义显式写出。
- **官方检查的边界**：`sing-box check` 只做解析和初始化，不执行完整启动；审核发现“不存在的出站”“组自引用”它也会放过。这两类现在由生成器在写盘前自己检查。
- **生成流程**：全部成功才替换；但进程被强行终止或断电时仍可能留下 `.new-*` / `.bak-*` 文件（见 `docs/01`）。
- **远程规则集跟随上游**（你的决定）：同一份配置在不同日期的匹配结果可能不同；审核建议的“锁定版本、审查差异后再发布”没有采用。
- **Braintree**：它是商家结账网关，PayPal 本身不依赖它，所以不放进 PayPal 组，仍走国外默认。
- **README 对“手动优先”的描述已收窄**：mihomo 按设计实现；Loon 的嵌套、Quantumult X 的恢复切回、各端的切换时限，都要真机确认。

## 2026-10-02 节点按名称分地区：做法与限制

规则、依据和核对结果见 `docs/02`“节点名称分地区”；怎么检查、怎么补见 `docs/01`。和使用直接相关的：

- **只看名字**：判断的是“名字写的是哪里”，不是节点实际从哪里出去。机场把名字写错、或者同一个名字换了落地，这里发现不了；实际出口仍要实测登记（`docs/05`）。
- **Loon、Quantumult X 上没有验证过**（最要紧的一条）：地区筛选正则从每条几百字节变成了约 10 KB（Loon 配置 55 → 126 KB，Quantumult X 51 → 326 KB，因为它没有引用机制，26 个策略各写一遍）。这些正则在 ICU 正则引擎上跑过、结果与期望一致，但“这两个 App 用的是 ICU”是推断，App 自己对一行的长度、对这些写法有没有限制也不知道。导入后请先按 `docs/09` 第 1 节看地区组里的节点对不对；有问题先切回上一版配置（统一源 2026.09.30-1），再告诉我现象。如果确认是正则太长造成的，光删少用的城市帮助有限（我试过：把美国和其他国家的词表都砍到只剩几个，每条仍有 3–5 KB，因为国旗、中转这些判断本身就占一半）；那时需要给这两个 App 另出一套短写法（只做“名字里有这些词”的简单匹配，不处理中转），这一版没有做。
- **Quantumult X 的“自动”“负载均衡”**：官方 `sample.conf` 的注释说 `server-tag-regex` 只对 static、available、round-robin 三种策略生效，同一文件的示例又把它写在 dest-hash 和 url-latency-benchmark 上。本项目的“X·自动”用 url-latency-benchmark、“X·负载均衡”用 dest-hash（上一版也是这样）。如果注释是对的，这两个组里不会按地区取到节点。要在设备上看这两个组的成员确认；确认不生效时，这两种模式在 Quantumult X 上需要换实现或去掉。
- **说不清落地的名字会同时进两个组**：例如 `日本-美国 01`、`🇯🇵🇺🇸 01`。这样不会漏节点，但“日本·自动”可能测速选中一个实际落地在美国的节点。检查工具会把这类节点单独列出来，可以在 `local.yaml` 的 `node_names.assign` 里指定归属。
- **香港让位是一个取舍**：`香港-日本 01` 归日本、`港美 IEPL` 归美国，因为香港在这类名字里多半是中转。少数机场反过来写（先写落地、后写入口，又不带“中转”字样）时会分错，例如把落地香港的 `日本-香港 01` 归到日本；这种名字用 `assign` 指定。
- **没有收的写法会进“其他地区”**：单个字的简称（日、美、韩、台、新）、`LA`、`SEA`、`SJ`、紧挨着字母的代码（`HKIPLC01`）、其他国家只写两三位代码（`DE-01` 本来就该进其他地区）。“其他地区”是纯手动组，这些节点不会被自动模式用到，但也不会丢；检查工具会列出来。
- **已知会分错的写法**（记在 `tests/node_names.yaml` 的 `known_limits`）：`港转美 01` 归香港（认得“港”在中转位置，认不出单个字的“美”；检查工具会列在“按中转 / 让位规则判断”里）；先写落地、后写入口又不带“中转”字样的名字（见上一条香港让位）。遇到时用 `assign` 指定，或把写法告诉我。
- **同名地**：`San Jose` 按美国算（哥斯达黎加首都同名）、`Newark` / `Portland` / `Columbus` 按美国算；`奥克兰`、`圣地亚哥`、`Georgia`、`Vancouver` 因为歧义没有收进美国。
- **信息节点靠词表识别**：`剩余流量`、`套餐到期`、`过滤掉 N 条线路`、`官网` 等（依据 V2Board、Xboard 面板源码里写出的提示行，以及常见写法）。机场自创的提示行如果不含这些词，会进“其他地区”；真节点的名字里如果恰好有这些词（例如名字里带“订阅”“公告”），会被当成信息节点、哪个组都不进——检查工具的“当成信息节点”一栏会列出来。
- **样本不是真实订阅**：498 个带期望的节点名是我按常见写法归纳和针对规则边界写的，另有 CLDR / 时区库的独立名称；它们不对应任何一家机场。等你发来更多机场的节点名（截图或文本，只要名字），我用检查工具核对后再补词表。
- **Clash Verge Rev / Clash Meta for Android**：配置里用了 YAML 的锚点 / 别名（同一条正则只写一次）。mihomo 内核读取和实际分组已验证；客户端界面层自己处理配置（合并、脚本）时是否原样保留没有验证，锚点 / 别名是 YAML 标准写法。
- **手机上的耗时是估算**：这台机器上 300 个节点 Loon 约 30–40 毫秒、Quantumult X 约 100–140 毫秒（ICU，含调用开销），手机会慢几倍；没有实测。
