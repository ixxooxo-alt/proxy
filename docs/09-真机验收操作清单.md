# 真机验收操作清单

对应统一源 2026.09.23-2 生成的配置。可以你自己做，也可以让一个能访问你电脑的 AI 帮你读取 Clash 的连接记录（见第 6 节，那一节是写给它的）。结果填进 `docs/05-验收记录.md` 的“真机验收清单”表格；分析报告和截图发回来，由我对照统一源修改规则。

手机上的 Loon、Quantumult X、SFA、Clash Meta for Android 只能你自己操作。电脑上的 Clash Verge Rev 可以用 `tools/check_connections.py` 自动判断每个连接走得对不对。

## 0. 开始之前（安全）

- 不要在正在跑 Grok bot / Cursor 调度的那台电脑上直接换配置。先确认两件事：能一键切回旧配置；就算代理完全不通，也知道怎么关掉系统代理 / TUN 恢复上网。
- 新配置用“新增配置 / 订阅”的方式导入，保留旧的，不要覆盖。
- 订阅链接只在你自己的设备上填：在电脑上用 `SUB_URLS='你的订阅' python3 build.py` 生成 `dist/private/` 里的版本，或者在客户端里把占位链接换掉。填好订阅的文件、控制接口的密钥，不要发给任何人，包括我。
- 测试期间关掉无关的网页和应用。连接记录会列出你访问过的网站，发出去之前自己先看一眼。

## 1. 导入与基础检查（每个平台做一次）

| 检查 | 怎么做 | 通过标准 |
|---|---|---|
| 客户端版本 | 在客户端“关于”里看 | 记下来 |
| 能导入 | 导入配置 | 不报错；sing-box 能启动 |
| 节点分组 | 打开“香港·自动”“日本·自动”等组 | 只有对应地区的节点；“其他地区”里没有港日韩台新美节点；“剩余流量”“到期”这类信息节点不在任何组里 |
| 业务组齐全 | 翻一遍策略组 | 41 个业务组都在，第一项是默认出口（OpenAI 默认日本、Netflix 默认“Netflix·解锁入口”、Apple 默认 DIRECT 等，完整列表见 `source/groups.yaml`） |
| Quantumult X 专项 | 看策略页 | `Apple Music/TV`、`Disney+`、`PayPal·美国固定` 这类带 `/`、`+`、空格、`·` 的名字能正常显示，规则里能用 |
| Loon 专项 | 打开“香港·手动优先”的成员列表 | 记录成员里有没有“香港·手动”“香港·自动”两个组：有，说明嵌套生效；只有节点，说明退化成同地区顺序故障转移 |
| sing-box 专项 | 看地区组 | 每个地区只有“自动”“手动”两种；某地区没有节点时，该组指向“无可用节点” |

## 2. 分流检查（只测你实际用的服务）

**电脑（Clash Verge Rev）**：测一个服务之前先关掉浏览器或那个 App，让它重新建立连接；然后用 1–2 分钟，再看“连接”页面（每条连接会显示命中的规则和组），或者按第 6 节采集记录，用工具分析。

**手机**：用一遍，确认功能正常。App 里如果有请求记录 / 日志页面，截图保存。

每个服务的通过标准：

1. 功能正常：能登录、能播放、能收发。
2. 这个服务自己的主机进了“应进的组”。
3. 没有这个服务自己的主机掉进国外兜底（规则是 `GeoSite(geolocation-!cn)` 或 `Match`、组是国外默认）。有的话就是漏掉的域名，记下主机名。
4. 登录、验证码、统计、公共 CDN 这些第三方主机走 Google、国外默认等其他组，属于正常，不算错。

## 3. 广告与例外

| 检查 | 怎么做 | 通过标准 |
|---|---|---|
| 广告拦截 | 打开一个有广告的网页或 App | 广告主机命中“广告拦截”（REJECT） |
| 验证邮件链接 | 点一封注册 / 验证邮件里的链接（常经过 *.ct.sendgrid.net） | 能打开，走国外默认 |
| 支付与人机验证 | 打开一个 Stripe 结账页、一个带 Cloudflare 验证的页面 | 能正常加载，走国外默认 |
| 例外的去向 | 看连接记录 | s.youtube.com 进 YouTube；copilot-telemetry.githubusercontent.com 进 Copilot；collector.github.com 进 GitHub |
| 已知会被拦的 | 需要 Google Analytics 后台的话打开 analytics.google.com | 会被拦（跟随上游广告集合）。需要用时，在 `source/adblock.yaml` 的误杀例外里加上再重新生成 |

## 4. 故障切换与选择保持

| 检查 | 怎么做 | 通过标准 |
|---|---|---|
| 手动优先 → 自动兜底 | 在“日本·手动”里选一个测速超时的节点，再用一个走日本的服务 | 几分钟内自动换到“日本·自动”里可用的节点，不跨国、不直连。记下用了多久 |
| 恢复切回 | 把“日本·手动”换回可用节点 | 流量回到手动选的节点 |
| 整个地区没有节点 | 如果订阅里某个地区一个节点都没有，把一个业务组切到这个地区 | 连接失败（被拒绝），不能直连、不能跑到别的国家 |
| 选择保持 | 改几个组的选择后重启客户端，再更新一次订阅 | 选择都还在 |
| PayPal 独立 | 把“国外默认”切到香港 | PayPal 仍然走美国节点 |

## 5. DNS、IPv6、局域网

| 检查 | 怎么做 | 通过标准 |
|---|---|---|
| 局域网 | 访问 NAS、打印机、路由器后台 | 能访问，走 DIRECT |
| IPv6（TUN 模式下） | 运行 `nslookup -type=AAAA www.google.com` | 没有返回 IPv6 地址 |
| DNS 泄漏（可选） | 打开一个 DNS 泄漏测试网站 | 看到的 DNS 服务器不是你本地运营商的 |
| 覆盖范围 | 分别测浏览器、命令行（例如 `curl.exe -I https://www.google.com`）、后台同步类应用 | 都受规则控制；系统代理模式下命令行可能不走代理，这时记下来 |

## 6. 写给代为检查的 AI

你的任务是读取这台电脑上 Clash Verge Rev（mihomo 内核）的连接记录，用本项目的工具判断分流是否正确，把报告交给用户。

**约束**

- 只读：不修改客户端配置，不切换配置 / 订阅 / 节点，不开关 TUN 或系统代理。需要改任何设置（例如打开外部控制器）先问用户。
- 不要执行 `DELETE /connections`，除非用户同意：它会中断所有正在进行的连接，包括下载和通话。让用户关掉浏览器或 App 再测，效果一样。
- 控制接口密钥、订阅链接、节点服务器地址不要写进报告，也不要发给任何人。交给用户的是工具生成的报告，不是原始记录。
- 需要登录账号的服务由用户自己操作。你只负责采集和分析；如果你能控制浏览器，只打开不需要登录的公开页面。
- 发现规则问题只报告，不要自己改 `source/`。用户同意改的话，按 `README.md`“改规则”的流程做，每条规则写明证据。

**步骤**

1. 找控制接口的地址和密钥。优先在 Clash Verge Rev 的设置里看“外部控制器”；也可以读它的运行时配置 `clash-verge.yaml` 里的 `external-controller` 和 `secret` 两行。这个文件一般在 Windows 的 `%APPDATA%\io.github.clash-verge-rev.clash-verge-rev\`、macOS 的 `~/Library/Application Support/io.github.clash-verge-rev.clash-verge-rev/`，以实际安装为准。如果外部控制器没有开，问用户是否打开（只监听 127.0.0.1，设置密钥）；用户不同意，就改用下面第 5 步的“复制日志”办法。直接运行本项目 `mihomo-core.yaml` 时，地址是 `127.0.0.1:9090`，没有密钥。
2. 确认接口能用，并记下内核版本（Windows 请用 `curl.exe`，PowerShell 里的 `curl` 是别的命令）：
   ```
   curl.exe -s -H "Authorization: Bearer <密钥>" http://127.0.0.1:<端口>/version
   ```
3. 每个服务单独采集一次。开始采集后告诉用户“现在开始用某某服务”，时间到了自动停止：
   ```
   curl.exe -sN --max-time 180 -H "Authorization: Bearer <密钥>" "http://127.0.0.1:<端口>/logs?level=info" -o netflix.jsonl
   curl.exe -s -H "Authorization: Bearer <密钥>" http://127.0.0.1:<端口>/connections -o netflix-connections.json
   ```
   第一条收集这 3 分钟里每个新连接命中的规则和组（到时间 curl 会报超时，属于正常，文件已经写好）；即使配置里 `log-level` 是 warning，这个接口也能收到。第二条是使用结束时仍在活动的连接，带进程名，用来区分浏览器和其他程序的流量。
4. 分析（在本项目目录下运行，需要 Python 3.10+ 和 PyYAML；Windows 用 `python`）：
   ```
   python3 tools/check_connections.py --service netflix netflix.jsonl netflix-connections.json --out netflix-报告.md
   ```
   退出码 1 表示有连接和统一源不一致，先确认客户端用的是这一版配置（`dist/manifest.json`）。报告里“落入国外兜底”的主机，就是可能漏掉的域名，要结合第 2 节的通过标准逐个判断。
5. 没有控制接口时：让用户在 Clash Verge Rev 的“日志”页面把级别设为 info，用完服务后全选复制，粘贴成文本文件，同样交给工具分析：`python3 tools/check_connections.py --service netflix 复制的日志.txt`。
6. 把各服务的报告、内核版本、客户端版本交给用户。

## 7. 结果怎么交回

- 你自己做的：填 `docs/05` 的表格，附上截图（连接页面、策略组成员、出错画面）。
- AI 帮你做的：各服务的 `*-报告.md`，加上客户端和内核版本。
- 发回来以后，我会对照统一源判断是规则问题、客户端差异还是节点问题，修改后重新生成配置，并把结论记进 `docs/05`。
