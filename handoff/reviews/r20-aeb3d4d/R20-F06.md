# R20-F06：mihomo 的 DNS 失败仍被概括成所有未分类网站打不开

**确认；P2；文档不符。** 不是新发现的配置分流错误。

## 位置

- docs/10-简易版框架.md:171，第 6.4 节开头；同文件:233、241 的后果概括。
- docs/06-已知限制与待决事项.md:13（第 23 项）、:330 附近“境外DNS用的节点挂了”。

## 问题和依据

这些段落把 mihomo、sing-box 合在一起说“没被规则认出的网站都打不开”。但 docs/10:165 正确记载：mihomo 为 GEOIP 判断解析失败后，会落到“国外默认”，并不一定中止连接。

已有 E6 原始记录直接构成反例：[report.json](https://github.com/ixxooxo-alt/proxy/blob/aeb3d4dcb157164a572f367c4671091913283f11/handoff/notes/simple_mihomo/runs/e6/report.json)，phases 中的 dns_series：

- dns-refuse：第一个结果为 node=n5，之后第 2.12 秒才变成 node=direct。
- dns-blackhole：第 5.07、12.14 秒结果为 node=n5，第 14.19 秒才为 node=direct。

n5 是当时正常的“国外默认”节点。实验里的连接在 DNS 尚未恢复时已经经代理完成；“恢复”计量的是恢复正确的国内直连路径，不是此前 HTTP 都打不开。这只说明实验台，不保证真实国内网站接受境外访问。

## 建议

分客户端和路径写：sing-box 未分类域名在 resolve 失败时连接失败；mihomo 的这类 TCP 路径可能解析超时后落到国外默认，造成原本应直连的国内站走代理、变慢或被网站拒绝，是否可用取决于所选节点及目标。需要本机解析地址的 UDP 等路径另行限定。保留 E6 的准确结果，不要把两种内核归成同一个“全打不开”后果。
