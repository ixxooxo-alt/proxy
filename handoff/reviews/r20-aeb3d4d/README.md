## 修复和设计的判断

### F01：Stash

两份简易版所有选择组明确 interval: -1，普通/严格版都覆盖；verify 拒绝缺失、布尔值、非负值。测试直接核对生成值和写盘前拦截，方向正确。负数检查与官方“负数关闭”一致。

完整版保持原样并把 select 默认 600 秒记录在 docs/06，是尊重“完整版不改”的合理处理，不应为修简易版顺带改完整版。是否去重测速、实际耗电流量仍应保持未验证。

### F02：两版分别转换节点

reserved_tags 按布局区分，build.py、check_official.py 都分别转换，按原名筛选的 renamed 映射分别传递；simple_conversion_notes 将两版命名差异和空 DNS 组另列出来，没有把差异伪装成相同。新增测试及 M197–M202 与修复对应，现有记录没有显示漏改调用入口。

### “完整版没变”的边界（建议 S01）

r20_full_private_same.py 用 shallow=False 逐字节比较，使用隔离副本和虚构输入，方法有效；但只是这份样例的结果，不是穷举。脚本发现差异只打印、仍可能退出 0，目前作为人工读结果的一次性记录可以；若以后用作自动验收门槛，必须断言当前完整版配置相同、且转换报告差异在允许范围内。

另外确实存在**自定义公共源**的边界：把两代模型的 health_check.interval_s 都设为 3600，r19 完整版 urltest 的 idle_timeout 为 30m，本版为 3600s（emit_singbox.py:169–172、219–222）。这是新 helper 同时作用于完整版造成的，不是 local.yaml 节点输入的回归；旧组合本来违反 interval <= idle_timeout，新行为修正了它。本轮不建议为了追求无条件逐字相同而恢复无效组合。应把“未变”限定为当前公开源和已核对的本地覆盖；不能宣称任意修改源之后都相同。

### 空“境外DNS”（建议 S02）

保留拒绝而不自动直连、不自动收进地区不明确的节点，符合已定隐私取舍。没有依据替用户放宽筛选。sing-box 已有报告提示，方向正确；建议提示更直接指向节点名称分类和经确认后的 local.yaml 修正。

还应补充冷启动边界：sing-box 没有有效远程规则缓存时，RemoteRuleSet.StartContext 首次 fetch 失败会返回错误，route.Router.Start 传播初始化错误，可能整个内核启动失败，不只是“部分网站打不开/更新不了”。依据：[rule_set_remote.go:95–143](https://github.com/SagerNet/sing-box/blob/v1.14.1/route/rule/rule_set_remote.go#L95-L143)、[router.go:135–157](https://github.com/SagerNet/sing-box/blob/v1.14.1/route/router.go#L135-L157)。这是源码推断，未在本轮手机运行；E7 换成本地规则集，不能覆盖它。有缓存和首次无缓存应分别列为验收场景。
