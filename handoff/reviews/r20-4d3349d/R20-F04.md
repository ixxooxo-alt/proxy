# R20-F04：把旧实验的“两倍间隔”套到新的 SFA 闲置参数上

**确认；P2；类别：文档不符。** interval 不超过 idle_timeout 的配置写法本身正确；错误在推导恢复时间。

## 位置

- `docs/10-简易版框架.md:158、164`：没在用时约两小时。
- `docs/06-已知限制与待决事项.md:14` 第 23 项：一小时/两小时、五分钟/十分钟、十分钟/二十分钟的对照及“SFA 开着时每五分钟测一遍”。
- `docs/03-DNS决策表.md:385` 同类说明。
- 新配置 `generator/emit_singbox.py:150–153`：简易版 interval 与 idle_timeout 均为 3600 秒。

## 为什么错、依据

[sing-box v1.14.1 protocol/group/urltest.go:257–279](https://github.com/SagerNet/sing-box/blob/v1.14.1/protocol/group/urltest.go#L257-L279) 的 PostStart 做初次检查；Touch 才启动定时器或刷新活跃时间。

[同文件:339–362](https://github.com/SagerNet/sing-box/blob/v1.14.1/protocol/group/urltest.go#L339-L362) 在定时 tick 先判断闲置时间；超过 idle_timeout 就**停止定时器并退出**，不是再等一轮继续查。重新使用时，Touch/loopCheck 会按活跃时间恢复检查。

旧的 595 秒记录来自 `handoff/notes/simple_singbox/driver.py:31–33、105–108`：idle_timeout 为 30m，interval 为 300s；实验没有进入与当前“interval = idle_timeout = 1h”相同的闲置状态。它支持那个实验的结果，不能支持新配置在长期闲置时固定两小时重测。

所以：
- 持续有新拨号、完全闲置、恢复使用，应分别描述；
- App 开着不等于组一直被使用；持久 DNS 连接复用也不等于持续调用 Touch；
- “每 N 分钟”以及“最长 N/2N 分钟”不能不加条件当成后台壁钟保证。

## 建议

保留一小时间隔的取舍，删除未经对应实验支撑的两倍时限；解释闲置会停止周期检查、再使用才恢复，以及恢复还需要测速耗时和健康候选。五/十分钟方案也写明活跃和 idle_timeout 条件，流量估算作为持续活跃时的粗估，不当作 App 开着就固定发生的消耗。

本轮补充探针受运行环境 netlink 权限限制未启动成功，因此这里的确认来自指定版本源码和旧实验参数对照，不声称测得真实一小时恢复时长。
